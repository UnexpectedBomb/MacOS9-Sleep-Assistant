# Building Sleep Assistant

Sleep Assistant is two pieces of code in one file: a 68K INIT (the startup code Mac OS runs) and a resident PowerPC
fragment (the driver that does the work), packed together with Rez into a MacBinary file.

## What you need

- A Mac running macOS, with [Retro68](https://github.com/autc04/Retro68) built for **both** targets: the PowerPC
  toolchain and the 68K one. The build script expects them under `~/Retro68-build` (`toolchain/` and
  `toolchain-m68k/`).
- CMake 3.13 or later.
- Python 3.

## Build

```bash
cd src
UWAKE_MODE=A ./build-usb-wake.sh
```

The result is in `src/build-A/`:

- `SleepAssistant.bin`: the MacBinary file to copy to a Mac and expand with StuffIt Expander;
- `Sleep Assistant`: the same file with its resource fork, for copying onto a disk image directly.

The script stops on the first failure. At the end it checks the package with `scripts/check-package.py`: the file's
name, type and creator, the version Get Info shows (`1.0.1`), that the code carries the same build tag as the version
resource, and that it is not a development build.

## Options

- `UWAKE_MODE=A` is the shipping design (Apple's USB stack kept running across the sleep). `UWAKE_MODE=B` builds an
  earlier experiment (Apple's PowerBook sleep mode) that is kept in the source for reference; it is not what ships.
- `UWAKE_PAINT=1` builds a development variant into `build-A-dev/` that paints a row of status squares at the
  bottom-left of the screen. It is for troubleshooting only; never install it for everyday use.
- `UWAKE_QTEST=1` with `BD=<a directory outside src/build*>` builds a self-test variant for the QEMU `mac99` machine,
  where QEMU's OHCI controller stands in for the NEC and a simulated sleep and wake run 90 seconds after startup.
  Adding `UWAKE_QTEST_LOGSMALL=1` caps the log at 120,000 bytes instead of 10,000,000 and trims it only when a write
  would pass that, so a single QEMU run exercises the cap.

## Reproducing the release

The 1.0.1 release file is `SleepAssistant_1.0.1.bin`, md5 `49fe590be314c842e2cab6fe010b878d`. It is this source's
build (md5 `0ba9d4b2377463b359eab3aa231ac37b`) passed through `scripts/scrub-build-user.py`, which replaces the build
machine's account name in two file paths that Retro68's prebuilt newlib compiles into the PowerPC code (inert
error-path strings) with a neutral word of the same length. Those 18 bytes are the only difference.

The 1.0 release file, `SleepAssistant_1.0.bin` (md5 `77ed30d195bd5a67fe4860eb78b5b93c`), was made the same way from
the build of the 1.0 source (tag `v1.0`) that was tested on the hardware.

A rebuild from this source has a different md5 again, because MacBinary stores the file's creation and modification
dates and because those two newlib paths name your own account. Apart from those, every resource (the PowerPC code,
the 68K INIT, the version resources and the icons) is byte-identical to the release's.

## Source

| file | what it is |
|---|---|
| `src/usb_wake_resident.c` | the resident PowerPC driver: the power handlers, the NEC's sleep and wake steps, the put-away hook, the recorder and the log |
| `src/usb_wake_init.c` | the 68K INIT that loads the driver at startup |
| `src/usb_wake.r` | the resources: version, the embedded code, the icon family |
| `src/sleep_assistant_icon.r` | the icon family, generated by `scripts/custom-icon-to-r.py` |
| `src/map_scan.h` | the logical-to-physical memory map the recorder reads through |
| `src/CMakeLists.txt`, `src/build-usb-wake.sh` | the build |
| `src/scripts/` | the build's helpers: `patch-pef-main.py` (makes the fragment a native driver), `set-custom-icon.py` (the Finder flag, the Mac name and the MacBinary CRC), `check-package.py`; and `scrub-build-user.py` (the publish step above), `custom-icon-to-r.py` (regenerates the icon resources), `test-map-scan.c` (a host test for `map_scan.h`) |

Internal names in the source still say "FW800 USB Wake", the project's working name before it became Sleep Assistant.
